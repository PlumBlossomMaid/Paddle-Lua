## 1. 做什么 / 不做什么

**做:** `nn.Layer` 基类(参数/子层注册、遍历、state_dict、train/eval、to)+ 约 40 个常用层
+ `nn.functional` + 初始化器 + 损失函数。

**不做:** `paddle.Model`(**永久排除**,由 PaddleOcean 的设计取代)。

**为什么这块贵:** 上游的 `paddle/nn/layer/*.py` 是**纯 Python 逻辑** ——
参数管理、名字作用域、递归遍历、钩子。这些没有 C++ 等价物可以绑,
只能一行一行用 Lua 重写。约 6000 行手写代码,是整个项目的成本重心。

**好消息:** 每一块都不难,难的是量。而且**语义可以直抄** —— 这属于 A1 类(能直接抄语义)。

## 2. 上游有什么可以用

| 出处 | 用途 |
|---|---|
| `python/paddle/nn/layer/layer.py` | `Layer` 基类的完整语义 —— 逐行翻译的蓝本 |
| `python/paddle/nn/layer/*.py` | 各层的实现,全部是对 `functional` 的薄封装 |
| `python/paddle/nn/functional/*.py` | 多数是对 `_C_ops.*` 的一行转发 |
| `python/paddle/nn/initializer/*.py` | 初始化器 |
| P3 生成的算子 | **`functional` 的绝大部分可以直接落到生成的算子上** |

**关键观察:`nn.functional` 里大部分函数是"参数整理 + 调一个算子"。**
既然 P3 已经生成了算子,`functional` 层的工作量比看起来小得多。
真正要手写的是 `Layer` 基类和各层的**参数管理**。

## 3. 设计

### 3.1 面向对象:用 `pl.class`

> ⚠️ **翻案记录(R18):** 本节曾选「自写 ~80 行的最小类系统」,理由是
> 「没有依赖,行为完全可控」,并明确否决了第三方 OOP 库
> (「引入依赖,且用户可能已有自己的 OOP 库,冲突」)。
> **该判断已被推翻。完整论证见 `plan/foundations.md` §1.6。**
> 一句话:依赖不是新增的(我们本来就需要 list + 5.1–5.4 兼容层 + 安全 table 读取),
> 而「用户已有自己的 OOP 库」恰恰是选 Penlight 的理由 —— 它是 Lua 生态的通用库。

**结论:用 `pl.class`**(vendored 在 `lua/paddle/_vendor/pl/`,受限子集,纯 Lua,零 C 依赖)。

```lua
local class = require "pl.class"

local Net = class(nn.Layer)
Net._name = "Net"                      -- 用于错误信息与 state_dict 前缀
function Net:_init()
  self:super()                         -- Penlight 的 super 调用
  self.fc = nn.Linear(784, 10)         -- 自动注册,见 §3.2
end
function Net:forward(x) return self.fc(x) end
```

`class.Net(nn.Layer)` 这种写法 Penlight 会自动设 `_name` 并在当前环境创建变量;
`Net = class(nn.Layer)` 不会。**示例与生成代码一律显式设 `_name`**,不依赖调用形式。

`pl.class` 的四个坑(`super` 是保留的实例字段名、`class.cast` 禁用、
不要用 `require("pl.class").class`、默认 `__tostring` 会读 `obj._class`)
已在 `plan/foundations.md` §1.5 逐条核实并给出出处,**开工前必读那一节**。

### 3.2 参数注册:自动注册(与 Python 对齐)

```lua
function Net:_init()
  self:super()
  self.fc = nn.Linear(784, 10)      -- 自动注册,不需要 add_sublayer
end
```

**用户不需要多写任何东西。** 这与 Python 侧 `self.fc = nn.Linear(...)` 完全一致,
从 Python 迁移过来的代码可以逐行照搬。

#### 关键实现:实例表必须保持"raw 空"

> ⚠️ **翻案记录:** 曾判断"`__newindex` 只在键不存在时触发,重复赋值会静默漏注册,
> 所以必须显式注册"(旧 R16)。**这个判断只在朴素实现下成立。**

Lua 的 `__newindex` 确实只在 `rawget(self, k) == nil` 时触发。
所以只要**保证用户可见的字段永远不进 raw 表**,`__newindex` 就永远会触发:

```lua
local class  = require "pl.class"
local FIELDS = {}     -- 私有键,用户无法拼写出来

local Layer = class()

-- ① Penlight 的 _create 钩子:实例表由我们造,在 _init 之前就装好 FIELDS
--    出处:pl/class.lua 的 mt.__call —— if rawget(c,'_create') then obj = c._create(...) end
Layer._create = function()
  local o = {}
  rawset(o, FIELDS, {
    params = {}, sublayers = {}, buffers = {}, plain = {},
    order  = {},          -- 插入顺序,见下
    training = true,
  })
  return o                -- 实例的 raw 表里只有 FIELDS 这一个键
end

-- ② Penlight 的 _class_init 钩子:每创建一个子类就跑一次
--    必须走这里 —— pl/class.lua 里 `c.__index = c` 是无条件硬编码的,
--    只在基类上设 __index 会被子类创建时覆盖掉
Layer._class_init = function(c)
  c.__index    = layer_index
  c.__newindex = layer_newindex
end

-- ③ 基类自己不经过 _class_init,要单独设一次
Layer.__index    = layer_index
Layer.__newindex = layer_newindex

layer_newindex = function(self, k, v)          -- 永远触发
  local f = rawget(self, FIELDS)
  unregister(f, k)                             -- 覆盖/置 nil 时先摘掉旧的
  if     is_parameter(v) then f.params[k]    = v; push_order(f, k)
  elseif is_layer(v)     then f.sublayers[k] = v; push_order(f, k)
  elseif is_tensor(v)    then f.buffers[k]   = v; push_order(f, k)
  elseif v ~= nil        then f.plain[k]     = v end
end

layer_index = function(self, k)                -- 永远触发
  local f = rawget(self, FIELDS)
  local v = f.params[k];    if v ~= nil then return v end
  v = f.sublayers[k];       if v ~= nil then return v end
  v = f.buffers[k];         if v ~= nil then return v end
  v = f.plain[k];           if v ~= nil then return v end
  return getmetatable(self)[k]                 -- 方法:走类表
end
```

最后一行值得说明:`getmetatable(self)` 就是这个实例的类表 `c`。
`c[k]` 走的是**类自己的元表** `{__index = base}`(`pl/class.lua` 里
`setmetatable(c, mt)` 且 `tupdate(c, base)`),
而 `c.__index` 是给**实例**用的 —— 两者互不干扰,继承链能正确走通。
**不要写成 `self.__index(...)`,那会无限递归。**

**这与 Python 的做法是同一个思路,不是取巧。**
`nn.Module.__setattr__` 也会把 parameter / module 从 `__dict__` 里**移出去**,
放进 `_parameters` / `_modules`,再靠 `__getattr__`(只在 miss 时调用)读回来。
我们只是把"从 `__dict__` 移出"换成"从一开始就不放进 raw 表"。

#### 三处必须处理对的边界

| 情形 | 正确行为 |
|---|---|
| `self.fc = A` 然后 `self.fc = B` | 两次都触发,B 替换 A,**在 order 里保持原位置**而不是追加 |
| `self.fc = nil` | 触发,从 params/sublayers/buffers 与 order 中摘除 |
| `self.x = 5` 然后 `self.x = someLayer` | 两次都触发(普通值也走 `plain`,不 rawset),类别从 plain 改为 sublayer |

**第三行是旧 R16 真正担心的场景,现在被"普通值也不 rawset"覆盖掉了。**

#### order 表不是可选的

Lua 的表**没有确定的遍历顺序**,而 Python 的 dict 是插入有序的。
如果不显式维护 `order`,`parameters()` 和 `state_dict()` 的顺序在每次运行都可能不同,
后果是:

- 优化器的参数顺序不稳定 → 固定种子也复现不了训练曲线
- `state_dict` 的落盘顺序不稳定 → 同一个模型存两次字节不同

**这是从 Python 迁移时最容易漏掉的一条**,因为 Python 那边是免费的。

#### `add_sublayer` / `add_parameter` 仍然保留

自动注册是默认路径,显式 API 作为补充继续提供:

```lua
self:add_sublayer("block_" .. i, block)     -- 动态名字
self:add_parameter("w", paddle.create_parameter{...})
```

理由:从 Python 迁移的代码里就有 `add_sublayer` 的调用,保留它是零成本的兼容性。
(其实 `self["block_" .. i] = block` 也能工作,两条路等价。)

#### 代价:每次字段访问都是一次元方法调用

| | 开销 |
|---|---|
| raw 表命中 | ~20 ns |
| 走 `__index` 函数 | ~60–100 ns |
| 一次 Conv2D kernel | 50–500 µs |

**差三到四个数量级。** 200 层的网络一次前向多花约 10–20 µs,
相对于毫秒级的计算量可以忽略。

**这是一次明确的取舍:用可忽略的运行时开销,换用户不需要学一套新写法。**

#### 副作用:`pairs(layer)` 看不到字段

raw 表是空的,所以 `pairs` / `next` 遍历不到任何东西。
必须提供替代品,而且要在文档里显眼位置说明:

```lua
layer:named_parameters()    -- 按 order 顺序
layer:named_sublayers()
layer:named_buffers()
```

Lua 5.2+ 可以设 `__pairs` 让 `pairs` 正常工作,**但 5.1 与 LuaJIT 不支持 `__pairs`**。
按 C3,不能依赖它 —— 5.2+ 上提供是加分,但文档和示例一律用 `named_*`。

#### 返回值:集合一律返回 `pl.List`

```lua
layer:parameters()   -- pl.List,不是裸表
layer:sublayers()    -- pl.List
layer:buffers()      -- pl.List
```

理由与边界见 `plan/foundations.md` §2。要点:
`named_*` 返回**迭代器**(与 Python 一致),`parameters()` 一类返回 `List`,
而 `x:shape()` 这种进热路径的小数据**返回裸表**。

### 3.3 层清单(v1 的 40 个)

| 类别 | 层 |
|---|---|
| 线性 | `Linear` `Bilinear` `Embedding` |
| 卷积 | `Conv1D` `Conv2D` `Conv3D` `Conv2DTranspose` |
| 池化 | `MaxPool1D/2D/3D` `AvgPool1D/2D/3D` `AdaptiveAvgPool2D` |
| 归一化 | `BatchNorm1D/2D/3D` `LayerNorm` `GroupNorm` `InstanceNorm2D` |
| 激活 | `ReLU` `GELU` `Sigmoid` `Tanh` `Softmax` `LeakyReLU` `SiLU` |
| 正则 | `Dropout` `Dropout2D` |

| 损失 | `CrossEntropyLoss` `MSELoss` `L1Loss` `BCELoss` `NLLLoss` |

### 3.4 train / eval 与 Dropout、BatchNorm

`self.training` 必须**递归**传播到所有子层。这是最容易写错的地方之一:
用户调 `net:eval()` 但某个子层没跟着切换,结果是"推理时结果随机波动",
而且**不报错**,只是数值不对。

验收里必须有一条:**遍历所有子层断言 `training` 标志一致**。

### 3.5 state_dict 的键名必须与 Python 一致

```
fc.weight    fc.bias
layer1.0.conv1.weight
```

**这是硬要求。** 键名不一致就意味着 Lua 存的权重 Python 读不了、
Python 存的权重 Lua 读不了,直接摧毁"Python 训练 / Lua 推理 / Lua 微调"的互通性。

分隔符是 `.`,容器用数字下标。**注意:容器下标用 0-based 还是 1-based?**

> ⚠️ **这是 1-based 决策唯一的破例,已确认采纳(D-R15)。**
>
> | | 下标基准 |
> |---|---|
> | `seq[1]` 访问第一个子层 | **1-based**(与全项目一致) |
> | state_dict 键名字符串 `layer1.0.conv1.weight` | **0-based**(与 Python 一致) |
>
> **破例范围严格限于序列化出来的键名字符串**,不扩散到任何 Lua 侧的访问语法。
>
> 之所以可以接受,除了"互通性摧毁不起"之外还有一条:
> **键名是给机器看的,普通用户不会去翻权重文件内部。**
> 真正会看到这些键名的场景只有两个 —— 调试权重加载失败、手工改名迁移权重 ——
> 而这两个场景恰恰都是"要和 Python 对齐"的场景,0-based 反而是对的。
>
> 代码里在生成键名处加注释说明原因,文档在"与 Python 互通"一节说明,
> **不在入门教程里提** —— 提了反而制造困惑。

## 4. 已知的坑

**① `__newindex` 与 Python `__setattr__` 语义不同**(§3.2)。
已通过"实例 raw 表保持空"规避,**但这条规避是脆弱的** ——
任何一处 `rawset(self, k, v)` 都会在那个键上永久关闭 `__newindex`。
`grep -n "rawset" lua/paddle/nn/` 的结果必须只有 `FIELDS` 那一处,
这条要写进 CI 检查而不是靠人记住。

⚠️ **Penlight 自己就有一处 rawset:** `pl/class.lua` 的 `call_ctor` 会
`rawset(obj,'super', ...)`,构造结束后再 `rawset(obj,'super',nil)` 清掉。
后果有两条:(a) `super` 是**保留的实例字段名**,用户的层不能有叫 `super` 的参数;
(b) CI 的 rawset grep 规则要把 vendored 的 `_vendor/pl/` 排除掉。
详见 `plan/foundations.md` §1.5。

**①b `class.cast` 必须禁用。** `cast(klass, obj)` 只是 `setmetatable(obj, klass)`,
不会跑 `_create`,得到的实例**没有 `FIELDS`**,第一次赋值就崩。CI grep。

**② `LayerList` 的长度与迭代在 5.1 上是静默失效的。**

`LayerList` **继承 `Layer`**(R22,`plan/foundations.md` §2.4)——
`ml:is_a(nn.Layer)` 为真,与 Python 的 `ModuleList` 是 `Module` 子类一致,
`parameters()` / `state_dict()` / `to()` / `train()` 的递归遍历不需要任何特例。

但因为实例的 raw 表必须保持空(§3.2),`#` 和 `ipairs` 都拿不到东西:

| | 5.1 / LuaJIT | 5.3 / 5.4 |
|---|---|---|
| `#ml` | 0 | 0 |
| `ipairs(ml)` | **一次都不迭代**(5.1 的 `ipairsaux` 用 `lua_rawgeti`) | 正常迭代(走 `lua_geti`,尊重 `__index`) |

**同一段代码 5.4 能跑、5.1 跑空,比全都不支持更糟。**

处置:
- 提供 `ml:len()` 与 `ml:iter()`,**文档、示例、生成代码一律只用这两个**
- **不去救 `ipairs`** —— 5.1 上救不了(没有 `__ipairs`)
- 加一条测试,把 `ipairs(ml)` 在五个版本上的实际行为**显式断言下来**,
  防止将来有人「顺手修好 5.4」而 5.1 仍然是坏的
- **绝不把整数键 rawset 进实例表**去换 `#`/`ipairs` 可用 ——
  那会让 `ml[2] = other` 不触发 `__newindex`,`parameters()` 返回旧层的参数,
  **训练静默收敛到错的地方**。见 `foundations.md` §2.4 的方案对比

另:`LayerList` 内部维护自己的长度字段,不用 `#`,因为 Lua 的 `#` 对含 nil 的表行为未定义。

**③ 深层网络的递归遍历要防栈溢出。** Lua 默认 C 栈深度有限,
`state_dict` 的递归实现在 100+ 层的网络上可能溢出。**用显式栈的迭代实现,不用递归。**

**④ 参数初始化的随机数必须与 Paddle 一致。** 否则"固定种子下 Lua 与 Python
训练曲线一致"这条验收永远过不了。要走 Paddle 的随机数生成器,不用 Lua 的 `math.random`。

**⑤ 别在 `forward` 里创建参数。** Python 侧有些层是 lazy 的,
第一次 forward 才知道输入尺寸。**v1 不支持 lazy 层**,所有参数在 `init` 里创建完。
理由:lazy 会让 `state_dict` / `parameters()` 在 forward 前后行为不一致,复杂度不值得。

## 5. 验收

- [ ] 40 个层逐个与 Python 对拍:**同一份权重、同一个输入,输出一致到 1e-6**
- [ ] `state_dict` 的键名与 Python **逐字符一致**(自动比对脚本)
- [ ] Python 存的权重 Lua 能加载,反之亦然
- [ ] `net:eval()` 后遍历所有子层断言 `training == false`
- [ ] `Dropout` 在 eval 下是恒等映射
- [ ] `BatchNorm` 在 eval 下用 running stats 而非 batch stats
- [ ] 200 层的深网络 `state_dict()` 不栈溢出
- [ ] 固定种子下参数初始化与 Python 逐位一致
- [ ] **自动注册在 `pl.class` 的三层继承上验证通过**(`Layer` → `MyBlock` → `MyNet`),
      确认 `_class_init` 确实覆盖掉了每一层的 `c.__index = c`
- [ ] **`print(layer)` 在 5.1 / 5.2 / 5.3 / 5.4 / LuaJIT 上都不崩**
      (Penlight 默认 `__tostring` 会读 `obj._class`,必须能经我们的 `layer_index` 回退到类表)
- [ ] **`LayerList` 满足 `ml:is_a(nn.Layer)`**,且不加任何特例就能被 `parameters()` 递归到
- [ ] **`ipairs(ml)` / `#ml` 的行为在五个版本上被显式断言**(不论结果是什么,断言的是「我们知道它是什么」)
- [ ] **`grep -rn "rawset" lua/paddle/nn/` 只有 `FIELDS` 一处**(排除 `_vendor/`)
