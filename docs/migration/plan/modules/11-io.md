## 3. 设计

### 3.1 Dataset 协议

Python 用 `__len__` + `__getitem__`。Lua 对应:

```lua
local class = require "pl.class"

local MyDataset = class(paddle.io.Dataset)   -- D25:类系统统一用 pl.class
MyDataset._name = "MyDataset"
function MyDataset:len() return 60000 end
function MyDataset:get(i) ... end            -- i 是 1-based
```

**`get` 而不是 `__index`。** 理由与 `09-nn.md` §3.2 同源:
Lua 的 `__index` 只在键不存在时触发,用它做数据访问会与实例字段冲突。
显式方法名更可靠。

**`i` 是 1-based。** 这是 D-R6 的直接后果,也是最自然的地方 ——
用户写 `self.samples[i]` 正好对上 Lua 表的 1-based,
`pl.List` 也是 1-based(D-R21),整条链上没有一处要换算。

**collate 的输出是 `pl.List`**(D-R21)。
但 **collate 内部的中间缓冲用裸表** —— 它在训练循环里每个 batch 都要造,
属于 `plan/foundations.md` §2.3 明确划出的热路径。

### 3.2 DataLoader 的迭代形式

```lua
for i, batch in paddle.io.DataLoader{ ds, batch_size = 64, shuffle = true } do
  -- i 是 1-based 的 batch 序号
  -- batch 是 { inputs, labels }
end
```

用 Lua 的**通用 for**,返回迭代器三元组 `(iter_fn, state, control)`。
这比 Python 的 `__iter__`/`__next__` 更简洁,而且**天然支持 break 后重新开始**。

### 3.3 为 P13 预留的接口

即使现在只有单 worker,以下必须现在就定下来:

| 预留项 | 现在的行为 | P13 时的行为 |
|---|---|---|
| `num_workers` 参数 | 只接受 0,传别的报"尚未实现" | 启动 Lanes 池 |
| `worker_init_fn` | 接受但不调用 | 每个 lane 启动时调 |
| Dataset 的**可序列化性**约定 | 文档里写明约束 | Lanes 传递时依赖 |
| `collate_fn` 的**纯函数**约定 | 文档里写明 | 在 worker 里执行 |

**最后两条最关键:** Lanes 传递到 worker 的东西必须是可跨 `lua_State` 传的。
如果 Dataset 里塞了 C 库句柄、文件句柄、upvalue 闭包,P13 时就传不过去。
**这个约束必须现在写进文档并在单 worker 阶段就"假装"遵守**,否则用户会写出
一堆到 P13 才发现传不了的 Dataset。

### 3.4 shuffle 的随机源

必须用 Paddle 的随机数生成器,不用 `math.random`。
理由:固定种子下要与 Python 的数据顺序一致,这是"训练曲线对拍"能成立的前提。

## 4. 已知的坑

**① Lua 的通用 for 会在 `iter_fn` 返回 nil 时终止。** 如果某个 batch 合法地是 nil
(比如空数据集),循环会提前结束。**约定:迭代器第一返回值是 batch 序号(永不为 nil),
batch 是第二返回值。** 这样天然规避。

**② `#` 不能用来数 Dataset 长度。** 用 `ds:len()`。见 `02-binding.md` §4 坑②:
Lua 5.1 对 userdata 不支持 `__len`,而且我们的 Dataset 是 table 不是 userdata,
但保持一致的方法名更省心。

**③ 数据是 CPU 上的,模型在 GPU 上。** 谁负责搬?
**约定:DataLoader 不搬,用户显式 `batch[1]:to("gpu:0")`。**
理由:自动搬运会掩盖真实的 H2D 开销,让用户误以为数据加载是免费的;
而且多卡时"搬到哪张卡"没有正确答案。

**④ `drop_last` 的默认值。** Paddle 默认 `False`,我们对齐。
但 BatchNorm 遇到 batch_size=1 的尾批会报错,**文档里要提示这个组合**。

## 5. 验收

- [ ] `for i, batch in DataLoader{ds, batch_size=64}` 正确迭代,`i` 从 1 开始
- [ ] `shuffle = true` 时,固定种子下顺序与 Python 一致
- [ ] `drop_last` 的两种取值下,尾批行为正确
- [ ] 中途 `break` 后重新开始迭代,行为正确
- [ ] `num_workers = 4` 报"尚未实现"而不是静默降级为 0
- [ ] `IterableDataset` 路径可用
- [ ] 60000 样本迭代 10 轮,内存不增长
