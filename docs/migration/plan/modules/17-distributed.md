## 1. 做什么 / 不做什么

**做:** 集合通信绑定(`all_reduce` / `broadcast` / `all_gather` / `barrier`)、

**不做:** **不宣称它可用。** 见 §5。

## 2. 这一阶段的特殊性:B2 类

`plan/overview.md` §2.0 的四象限里,本阶段是 **A1/B2** ——
**语义能直接抄,但当前环境测不了。**

四象限的裁决规则是:**A 与 B 冲突时,B 胜。**
即"测不了的代码,即使能直接抄,也是负债"。

**为什么是负债,而不是"先写着,以后测":**

> 单卡环境下,`all_reduce` 退化为恒等映射。
> `DataParallel` 退化为普通模型。
> **所有测试都会通过,所有代码看起来都是对的。**

这是最危险的一种状态 —— 不是"没测",而是"测了,而且通过了,但测试本身没有意义"。
一份跑绿了的无意义测试比没有测试更有害,因为它给人虚假的信心。

所以本阶段的第一条规则是:**所有产出必须显式标注"未在多卡环境验证"。**

## 4. 设计(纸面,未验证)

```lua
paddle.distributed.init_parallel_env()

local net = paddle.DataParallel(net)

-- 训练循环不变
```

启动方式:`paddle.distributed.launch` 的等价物是一个 Lua 脚本或 shell 脚本,
按 rank 设环境变量后启动 N 个进程。

**注意:这里是真·多进程**(每卡一进程),与 P13 的多线程 DataLoader 是两回事,
不要混淆。DataLoader 的 worker 在每个进程内部依然是 Lanes 线程。

## 5. 验收 —— 分成两级

### 5.1 现在能做的(单卡)

- [ ] `world_size = 1` 时,所有 API 可调用且不崩
- [ ] `all_reduce` 在单卡下是恒等映射(**并在代码注释里写明这条测试没有意义**)
- [ ] `DataParallel(net)` 后训练结果与不包装时逐位一致
- [ ] 所有公开 API 的文档字符串带 `[UNVERIFIED: multi-GPU]` 标记
- [ ] `process/status.md` 里明确记录"P17 未验收"

### 5.2 需要多卡环境(推迟)

- [ ] 2 卡 `all_reduce` 结果正确
- [ ] 2 卡数据并行训练,收敛曲线与单卡一致
- [ ] 梯度同步的正确性(手工构造不同梯度,验证求和)
- [ ] 一个进程崩溃时,其余进程不挂死

**5.2 全部通过之前,README 与文档里不得出现"支持分布式训练"字样。**
可以写"分布式 API 已实现,尚未在多卡环境验证"。
