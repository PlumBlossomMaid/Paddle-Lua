## 1. 做什么 / 不做什么

**做:** `paddle.save` / `paddle.load`,以及 `Layer:state_dict()` / `set_state_dict()`
的落盘格式。

**不做:** **不把纯 Lua pickle 解析器当作 M1 的阻塞项。**
这是本阶段最重要的一个判断,理由见 §3.1。

## 3. 设计

### 3.1 为什么 pickle 从"必做"降级为"加分项"

Python 侧 `paddle.save` 默认产出 pickle 格式。最初的判断是:
Lua 要读 `.pdparams` 就必须实现一个 pickle 解析器,而这是 M1 的阻塞项。

**这个判断是错的。** 因为:

- 我们**自己存的**东西可以用 `SaveTensor` 的格式,根本不经过 pickle
- M1 的验收是"MNIST 在 Lua 里训练收敛",全程不需要读 Python 存的权重
- 要读 Python 权重的场景是 P8(`jit::Layer` 推理),而那条路径走的是
  `paddle.jit.save` 的产物,**也不是 pickle**

所以 pickle 解析器的唯一价值是"读别人用 `paddle.save` 存的 `.pdparams`"。
这是真实需求,但**不阻塞任何里程碑**,放到 M2 作为加分项。

### 3.2 两种格式并存

| 格式 | 用途 | 实现 |
|---|---|---|
| **原生**(默认) | Lua 存、Lua 读 | `SaveTensor` / `LoadTensor` + 一份 Lua 写的 manifest |
| **pickle**(只读) | 读 Python 的 `.pdparams` | 纯 Lua pickle 解析器,M2 |

### 3.3 原生格式的布局

```
model.pdlua/                  ← 是目录不是单文件
├── manifest.lua              可读的 Lua 表:键名、shape、dtype、文件名
├── 0001.tensor               SaveTensor 产物
├── 0002.tensor
└── ...
```

**用目录而不是单文件,理由有三条:**

1. `SaveTensor` 只会写单个张量,拼容器格式要自己做,没必要
2. manifest 是**可读的 Lua 源码**,出问题时用户能直接看、直接改
3. 增量加载成为可能 —— 大模型只加载需要的部分

代价是不方便传输,所以额外提供 `paddle.save{obj, path, archive = true}` 打 tar 包。

### 3.4 manifest 的样子

```lua
-- GENERATED by paddle.save
return {
  format_version = 1,
  paddle_version = "3.5.0",
  entries = {
    { key = "fc.weight", file = "0001.tensor", shape = {784, 10}, dtype = "float32" },
    { key = "fc.bias",   file = "0002.tensor", shape = {10},      dtype = "float32" },
  },
}
```

加载时**不要自己写 `loadstring` + 空环境**,直接用 `pl.pretty.read`
(D25,基座见 `plan/foundations.md` §1.7)。已核实它的实现正是我们要的:

```lua
-- pl/pretty.lua:116-140
--   1. 必须以 `{` 开头,否则拒绝
--   2. 出现 `function` 关键字 -> 用 pl.lexer 二次确认后拒绝
--   3. utils.load(s, 'tbl', 't', {})   <- 空环境
--   4. pcall 前后保存/恢复全局环境
local manifest, err = pretty.read(src)
```

⚠️ **`pretty.read` 不防死循环**(`while true do end` 能过)。
- 我们自己 `paddle.save` 写出来的 manifest -> 用 `pretty.read`
- 用户给的路径下来路不明的 manifest -> 用 `pretty.load(src, {}, true)`(paranoid)

## 4. 已知的坑

**① `SaveTensor` 的格式稳定性未经核实。** 它是 `framework` 内部使用的函数,
上游没有承诺跨版本兼容。我们的 manifest 里写 `paddle_version`,
加载时版本不匹配要**警告而不是静默继续**。M0 第 19 项验证此事。

**② ~~`loadstring` 在 5.2+ 改名为 `load`~~ -> 用 `pl.compat.load`。**
不要在业务代码里写 `local loadstring = loadstring or load`。C11 规定兼容层只有一套。

**③ ~~空环境执行的写法五个版本不同,要封装 `sandbox_load()`~~ -> 已被 `pl.pretty.read` 覆盖。**
5.1 用 `setfenv`、5.2+ 用 `load(chunk, name, "t", env)` 的分支 Penlight 已经处理好了。
**我们少写一个安全相关的工具函数,这是 D25 最直接的收益** —— 沙箱是最不该自己写的东西。

**④ 别用 `os.time()` 做文件名。** 生成的 manifest 应该可重现,同一个模型存两次
应该得到相同的字节(除非权重变了)。理由同 `03-codegen.md` §3.5。

## 5. 验收

- [ ] 存 -> **重启进程** -> 读回,张量逐位一致
- [ ] GPU 张量存盘后能在 CPU-only 环境读回(place 转换正确)
- [ ] manifest 在空环境执行,注入 `os.execute` 的恶意 manifest 无法生效
- [ ] 含 `function` 的 manifest 被 `pretty.read` 拒绝(而不是执行)
- [ ] `format_version` 不匹配时给出明确警告
- [ ] 五个 Lua 版本互相读写兼容
- [ ] 1GB 模型的存/读耗时记录在案
